# Upgrade to Umbraco 19

From `18.x` (`[18.0.0,18.999.999)`, newest 18 release `18.3.1`) to `19.0.0-rc1` (tag
`release-19.0.0-rc1`). Branch `v19/dev`, cut from `v18/dev` at `1287231`.

**Targets CMS release:** `release-19.0.0-rc1`. While this is a pre-release, the package ships
as `19.0.0-rc.1` too.

This run also moves the CO2 dashboard onto the shared
[Umbraco.Analytics.UI](https://github.com/umbraco/Umbraco.Analytics.UI) components, at the
maintainer's request. That is a redesign, not an upgrade fix, so it has its own task group
("Analytics.UI"), after the version bump.

## Analytics.UI

`Umbraco.Analytics.UI` 19.0.0-rc.1 (NuGet, puts the files on the site) and
`@umbraco/analytics-ui` 19.0.0-rc.1 (npm, types only). Umbraco.AI 19 already depends on it
(`[19.0.0-rc.1, 19.999.999)`), so it's on every site that runs this package.

| Ours | Becomes |
|---|---|
| `summary/summary-card(s)` | `uaui-kpi-tile`: label "Estimated CO2e", midpoint as `value`, "Likely range a–b" as `detail` |
| `summary/equivalent-strip` | Kept, restyled with `UauiPaletteStyles` |
| `trend/trend-chart` | Kept, but on the shared `@umbraco/analytics-ui/external/chart.js` with `uauiChartColors`/`uauiChartOptions`/`uauiWatchTheme`. `uaui-time-series-chart` has no low–high band, so it would drop the range |
| `by-model`, `by-feature` tables | `uaui-data-table` (client mode), plus a small custom CO2 cell for figure + range + warnings |
| `method/` modal | Kept |
| Loading / error / empty states | uaui `loading`/`error` props, `uaui-error-state`, `uaui-empty-state` |
| `header/range-select` | Removed: the tab reads Umbraco.AI's header picker |

Wiring: NuGet reference from `Web.StaticAssets`; npm dev dependency; Vite already externalises
`@umbraco/*`; vitest needs an alias to local stubs, because the npm package has no runtime JS.
Our own `chart.js` dependency goes, so the bundle shrinks and the site loads one copy.

## Decisions

- 13-11-2026: Trend chart stays our own Chart.js chart on the shared copy, because `uaui-time-series-chart` can't draw the low–high range. (Proposed; confirm with the plan.)
- 13-11-2026: Compare-to-previous-period is out of scope; follow-up.
- 13-11-2026: Date range comes from Umbraco.AI's header picker; our own picker is removed. "Last 24 hours" goes; the header's whole-day presets replace it. Read through the workspace context until Umbraco.AI exports its token.

## Breaking changes for consumers

- Requires CMS 19, Umbraco.AI 19.0.0-rc.1 or later, and .NET 11.
- The CO2 tab's saved range choice (`date-range-store.ts`) is dropped: the tab now follows Umbraco.AI's header range. "Last 24 hours" is gone.
