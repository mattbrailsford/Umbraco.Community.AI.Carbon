# Upgrade to Umbraco 19

From `18.x` (`[18.0.0,18.999.999)`, newest 18 release `18.3.1`) to `19.0.0-rc1` (tag
`release-19.0.0-rc1`). Branch `v19/dev`, cut from `v18/dev` at `1287231`.

**Targets CMS release:** `release-19.0.0-rc1`. While this is a pre-release, the package ships
as `19.0.0-rc.1` too.

This run also moves the CO2 dashboard onto the shared
[Umbraco.Analytics.UI](https://github.com/umbraco/Umbraco.Analytics.UI) components, at the
maintainer's request. That is a redesign, not an upgrade fix, so it has its own task group
("Analytics.UI"), after the version bump.

## Decisions

- 13-11-2026: The hourly/daily line is found by comparing one hourly and one daily series read: a UTC day whose daily request count is more than its hourly count had hourly rows cleaned, and the line is the day after the last such day (never after today). Quiet days prove nothing, so they never move it. Replaces two rounds of single-day probes that confused quiet days with cleaned ones. Temporary until Umbraco.AI exposes its own boundary (Umbraco.AI PR, `GetStatisticsCoverageAsync`).
- 13-11-2026 (maintainer): The hourly/daily split line is found from the data, with small bounded checks through the public `IAIUsageAnalyticsService`, not worked out from the clock. That matches Umbraco.AI's own reader when the cleanup job lags a day or retention is raised. The interface keeps the new zone overload abstract: making it the default would silently drop the zone in replaced services.
- 13-11-2026: Daily estimates must use the viewer's local days, not UTC days, so the CO2 tab matches the Usage tab. Added as task 7b (a server change) instead of shipping the gap: west of UTC the first day was dropped and Daily labels ran a day late. `IAIUsageOverviewService` can't be used: it has no feature-type dimension or per-model series.
- 13-11-2026: States: one page-level `uaui-error-state` with a single Retry (one request feeds the whole page); 403 shows a lock message with no Retry and no tiles; the trend chart's loading placeholder is our own, matching Analytics.UI's internal `uaui-skeleton`. The method button stays disabled while loading or in error, because its content comes from the estimate response and no figures are shown.
- 13-11-2026: Tables use `uaui-data-table` (client mode) with two small cells of our own: `aicarbon-co2e-cell` (figure, likely range, warnings) and `aicarbon-missing-text-cell` (shows "—" but sorts missing values last; Analytics.UI's text cell has no placeholder). By Model rows are keyed `[providerId, modelId, usage]` so task 8's compare matches a model whatever its status. By Feature has no search (at most around 5 rows).
- 13-11-2026: KPI tile copy: detail lines carry the range without a unit ("Likely 1.5–2.4"; the unit is on the value line), and the 4th tile is "Not Estimated" / "Models not in the totals", so all four fit one line at 1440. The tile's uppercase label style shows "CO2E"; accepted as Analytics.UI's look.
- 13-11-2026: Trend range band has no border and a 45% alpha fill of the palette's `series[0].bar`, under a 2px `series[0].line` midpoint line. A border in the line colour made the 168-bar hourly view unreadable.
- 13-11-2026: Bundled `chart.js` moved 4.5.1 → 4.6.1 in task 2: npm satisfied our `^4.5.1` with the exact 4.6.1 that `@umbraco/analytics-ui` pins. Task 3 removes our copy.
- 13-11-2026: Root `package.json` pins `typescript ^5.9.2` (dev only). Without it npm hoists TypeScript 7, which has no `ts.SyntaxKind` and crashes hey-api 0.99. Remove only once hey-api supports TS 7.
- 13-11-2026: Demo scripts install Clean and Umbraco.AI with `19.*-*` (prerelease wildcard), so they follow RCs without edits. Only 19.x matches.
- 13-11-2026: Trend chart stays our own Chart.js chart on the shared copy, because `uaui-time-series-chart` can't draw the low–high range. (Proposed; confirm with the plan.)
- 13-11-2026: Compare-to-previous-period is in scope (task 8), driven by the header picker's compare setting.
- 13-11-2026: Date range comes from Umbraco.AI's header picker; our own picker is removed. "Last 24 hours" goes; the header's whole-day presets replace it. Read through the workspace context until Umbraco.AI exports its token.

## Breaking changes for consumers

- Requires CMS 19, Umbraco.AI 19.0.0-rc.1 or later, and .NET 11.
- The CO2 tab's saved range choice (`date-range-store.ts`) is dropped: the tab now follows Umbraco.AI's header range. "Last 24 hours" is gone.
- `IAICarbonEstimateService` gains `GetEstimateAsync(from, to, granularity, TimeZoneInfo? timeZone, ct)` with no default implementation (task 7b). Custom implementations registered with `AddUnique<IAICarbonEstimateService, …>()` must implement it; the Management API always calls it with the viewer's zone. The old 4-argument overload stays as a default method meaning UTC days.
- `GET /umbraco/ai-carbon/management/api/v1/estimate` takes an optional `timeZone` (IANA). Without it, Daily buckets are UTC days as before, so this part is additive.
